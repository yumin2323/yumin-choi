Yetter의 워크플로우 화면에서는 여러 노드가 이어져 차례로 실행됩니다. 노드마다 진행 상태와 결과가 서버에서 SSE(Server-Sent Events)로 실시간 전달됩니다.

## 두 가지 문제

### 이벤트가 몰리면 화면이 버벅였습니다

실행이 활발할 때는 짧은 시간에 많은 이벤트가 들어옵니다. 이벤트 하나가 도착할 때마다 상태를 갱신하면, 그때마다 워크플로우 전체가 다시 그려질 수 있습니다. 노드가 많은 워크플로우일수록 부담이 커졌습니다.

### 이전 실행 결과가 최신 화면을 덮어썼습니다

사용자가 실행을 다시 시작하면, 앞선 실행의 이벤트가 늦게 도착하는 경우가 있었습니다. 이 이벤트를 그대로 반영하면 **이미 지난 실행의 결과가 최신 화면을 덮어쓰는** 문제가 생겼습니다.

## 해결

### 이벤트를 묶어서 처리하기

이벤트를 받는 즉시 상태에 반영하지 않고, 짧은 구간 동안 모아 한 번에 반영했습니다. 같은 노드에 대한 이벤트가 여러 번 들어오면 마지막 상태만 남기면 됩니다.

### 바뀐 노드만 다시 그리기

상태를 노드 단위로 나누고, 각 노드가 자기 상태만 구독하도록 했습니다. 이벤트 묶음이 반영될 때 **변경된 노드만 다시 렌더링**되고, 나머지 노드와 캔버스는 그대로 남습니다.

### 실행마다 식별자를 두고 확인하기

실행을 시작할 때마다 새 식별자를 두고, 도착한 이벤트가 지금 화면이 보여 주는 실행의 것인지 확인한 뒤에만 반영했습니다. 아래는 개념을 단순화한 예시입니다.

```ts
function applyEvents(events: RunEvent[]) {
  // 지금 보고 있는 실행이 아닌 이벤트는 버린다
  const latest = events.filter((event) => event.runId === currentRunId);
  if (latest.length > 0) updateNodes(latest);
}
```

## 결과

이벤트가 몰리는 순간에도 워크플로우 화면이 부드럽게 유지되고, 실행을 다시 시작해도 이전 실행의 결과가 끼어들지 않게 됐습니다.

## 돌아보며

실시간 화면에서는 "얼마나 자주 그리는가"와 "무엇을 그려도 되는가"를 함께 다뤄야 했습니다. 앞의 것은 성능 문제이고, 뒤의 것은 정확성 문제입니다.
