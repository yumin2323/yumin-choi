# 블로그 썸네일 디자인 시스템

블로그 글 썸네일을 만들 때 따르는 규칙입니다. 구현은 `src/components/post-thumbnail.tsx` 한 파일에 있습니다. 파일 맨 위에 이 문서의 규칙이 토큰(`C`, `STROKE`, `RADIUS`, `BAR`, `DOT`, `SAFE`)과 공통 도형(`Box`, `Bar`, `GoldDot`, `flow`)으로 정의되어 있으니, 그림은 이것만 조합해서 그립니다. 새 숫자를 만들지 않습니다.

## 방향

썸네일은 실제 제품 UI의 스크린샷이 아니라 **제품 UI를 추상화한 설명용 다이어그램**입니다.

- 글의 핵심 아이디어 하나를 도형의 배치와 강조로 보여 줍니다.
- 글마다 완전히 다른 그림을 만들기보다, 같은 UI 언어(노드, 패널, 입력 칸, 스켈레톤 막대, 연결선)를 조합합니다.
- 사이트 전체의 editorial 톤을 해치지 않도록 조용하게 그립니다. 목록에서 제목보다 먼저 튀지 않아야 합니다.

## 캔버스와 안전 영역

| 항목 | 규칙 |
| --- | --- |
| 크기 | `viewBox="0 0 1200 630"` (1.91:1) 고정 |
| 모서리 | 캔버스 자체는 CSS로 `rounded-[10px]`. SVG 안에서 따로 그리지 않음 |
| 안전 영역 (`SAFE`) | 좌우 11%, 상하 13%. x 132~1068, y 82~548 |
| 크기 맞추기 | 그림은 안전 영역의 **가로와 세로를 모두** 채움. 썸네일마다 오브젝트 크기가 같아 보이도록 |
| 예외 | gold 점과 그 테두리는 안전 영역 밖으로 몇 단위 나가도 됨 |
| 구성 | 중앙 또는 약간 좌우 비대칭. 시선이 처음 가는 곳(강조 요소)은 항상 하나 |

1.91:1은 링크 미리보기(Open Graph) 이미지의 표준 비율입니다. 나중에 썸네일을 `og:image`로 그대로 쓸 수 있도록 16:9 대신 이 비율을 씁니다.

`transform`의 `scale`로 그림 크기를 맞추지 않습니다. 선 두께와 모서리가 함께 커지거나 작아져서 토큰이 깨지기 때문입니다. 좌표를 `SAFE` 기준으로 계산해서 그립니다.

## 색

색은 **직접 값을 쓰지 않고 변수만** 씁니다. 썸네일 전용 변수(`--thumb-*`)는 `globals.css`에 라이트와 다크 값이 따로 있어서, 테마를 바꾸면 썸네일도 따라 바뀝니다.

| 토큰 | 변수 | 쓰는 곳 |
| --- | --- | --- |
| `C.bg` | `--thumb-bg` | 캔버스 배경. 모든 글이 같은 배경 |
| `C.surface` | `--thumb-surface` | 노드, 카드, 패널, 입력 칸의 안쪽 |
| `C.line` | `--thumb-line` | 테두리, 연결선, 스켈레톤 막대 |
| `C.muted` | `--thumb-muted` | 강조하지 않는 키 막대, 이벤트 점, 비활성 glyph, 버려진 요소 |
| `C.accent` | `--accent` | 글의 핵심 아이디어 하나: 경로, 묶음, 바뀐 노드, 필요한 글자 |
| `C.accentSoft` | `--thumb-accent-soft` | 강조된 노드·박스의 안쪽 |
| `C.strong` | `--heading` | 강조된 glyph 글자 |
| `C.gold` | `--gold` | 결과 지점의 작은 점 **하나** |

- 한 썸네일은 **navy 계열 + gray 계열 + gold 점** 세 계열로만 그립니다. `accent`와 `accentSoft`는 같은 navy 계열로 칩니다.
- 다크 모드에서는 칸(`surface`)이 배경(`bg`)보다 **밝게** 떠 보이도록 값을 잡았습니다. 칸이 배경보다 어두우면 구멍처럼 보이고 비활성 요소가 묻힙니다.
- 투명도(`opacity`, `fillOpacity`)로 흐리게 만들지 않습니다. 흐린 요소는 `C.muted` 색을 그대로 씁니다. 투명도는 배경에 따라 결과가 달라져서 라이트와 다크의 대비가 어긋납니다.

### 배경 명도

- 모든 썸네일이 같은 배경(`C.bg`)을 씁니다. 글마다 배경색을 바꾸지 않습니다.
- 그림이 차지하는 면적도 비슷하게 맞춰서, 썸네일 전체의 평균 밝기가 테마별로 **±5** 안에 들게 합니다(0~255 기준).
- 현재 평균 밝기는 라이트 239~242, 다크 37~42입니다.

## gold 점

gold는 **결과 지점 하나**에만 씁니다. 결과 지점은 navy 강조 흐름이 끝나는 곳입니다. 경로의 마지막 노드, 묶음이 반영된 노드, 만들어진 폼, 줄어든 용량처럼요.

| 결과 지점의 모양 | gold 점 위치 |
| --- | --- |
| 박스(노드, 카드, 패널) | 오른쪽 위 모서리 |
| 막대 | 오른쪽 끝에서 20 떨어진 같은 높이 |

- 크기는 `GoldDot` 하나로 고정입니다. 반지름 9에, 배경색 테두리 3을 둘러 배경과 떨어뜨립니다.
- 선택된 요소나 변화 지점에 gold를 따로 찍지 않습니다. 그런 곳은 navy 강조로 표시합니다.
- 선이나 면을 gold로 칠하지 않습니다.

## 선과 모양

SVG 안의 숫자는 **1200 폭 viewBox 기준 단위**입니다. 글 페이지(720px)에서는 약 0.6배, 모바일(약 350px)에서는 약 0.3배, 넓은 화면의 목록(240px)에서는 약 0.2배로 줄어 보이므로, 실제 화면의 px로 정하지 않습니다.

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `STROKE.base` | 2 | 모든 평범한 선, 테두리, 연결선 |
| `STROKE.strong` | 3 | 강조된 선과 테두리, 흐름 점선, gold 점 테두리 |
| `flow` | `STROKE.strong` + `strokeDasharray="2 10"` + 둥근 끝 | 흐름을 나타내는 점선 연결선 (`--accent`) |
| `RADIUS.panel` | 16 | 큰 패널, glyph 칸 |
| `RADIUS.node` | 10 | 노드, 카드, 입력 칸, 이벤트 묶음 |
| `BAR` | 14 | 스켈레톤·데이터 막대 높이. 모서리는 높이의 절반(알약) |
| `DOT.base` / `DOT.strong` | 7 / 9 | 평범한 점 / 강조된 점 |
| 그림자, 그라디언트 | 없음 | |

비활성 요소를 점선으로 그릴 때는 `strokeDasharray`만 더하고 두께는 `STROKE.base`를 그대로 씁니다.

## 글자

- 제목, 설명, 숫자, 라벨 같은 글자는 넣지 않습니다. 글의 내용은 썸네일 아래 제목이 말합니다.
- 텍스트가 있어야 할 자리는 스켈레톤 막대로 대신합니다.
- 예외적으로 주제 자체를 보여 주는 기호나 glyph(`Aa`, `가`, `あ`, `{}`, `[]`, `</>` 등)는 쓸 수 있습니다. 이때 글꼴은 `style={{ fontFamily: "var(--font-sans)" }}`, 굵기는 600으로 사이트 글꼴을 따릅니다.

## 구성과 밀도

- **메인 모티프 1개 + 보조 요소 1~2개**
  - 예: 메인 = 워크플로우 카드 줄, 보조 = 이벤트 타임라인과 둘을 잇는 점선 하나
- 강조(`C.accent`)는 **하나의 아이디어**에만 씁니다. 경로 하나, 묶음 하나, 노드 하나처럼요.
- 나머지는 모두 gray 계열로 두어서, 강조가 없는 상태의 그림도 차분해야 합니다.
- 밀도 기준
  - 박스(노드, 카드, 패널, 칸)는 2~14개
  - 연결선은 20개 이하
  - 너무 비어 보이면 요소 수를 늘리기보다 요소를 키워 안전 영역을 채웁니다.
- 전·후 비교처럼 수치가 핵심인 글은 막대 길이를 실제 비율대로 그립니다. 예: 스크롤 프레임 글의 1692MB 대 898MB.

## 글 종류별 모티프

필수는 아니고, 새 글의 그림을 정할 때 출발점으로 씁니다.

| 글 종류 | 모티프 | 강조할 것 |
| --- | --- | --- |
| 성능·최적화 | 경로, 병목, 흐름 | 개선된 경로나 병목 지점 |
| 상태 관리·실시간(SSE) | 이벤트 스트림, 큐, 묶음 | 한 번에 반영되는 묶음, 바뀐 요소 하나 |
| 폼·스키마 | 트리, 필드, 입력 블록 | 스키마에서 폼으로 이어지는 필드 |
| 그래프 | 노드와 엣지 | 경로 하나 |
| 폰트 | glyph 칸 | 실제로 필요한 glyph |
| 데이터·차트 | 표 + 간단한 시각화 | 선택된 셀 범위나 막대 하나 |
| 배포·운영 | pipeline, 단계 | 지금 단계나 바뀐 단계 |
| 디자인 시스템 | 컴포넌트 블록, 토큰 | 토큰에서 컴포넌트로 이어지는 흐름 |

## 새 썸네일 추가하기

1. `src/components/post-thumbnail.tsx`에 그림 함수를 하나 만듭니다. 함수는 `<g>` 하나를 돌려주고, 배경은 공통 컴포넌트가 그리므로 넣지 않습니다.
2. 같은 파일의 `thumbnails`에 글의 slug를 키로 등록합니다. `label`에는 그림을 설명하는 한 문장을 적습니다. 스크린 리더가 읽는 대체 텍스트입니다.
3. 좌표는 `SAFE`에서 계산하고, 반복되는 요소는 배열과 반복문으로 그립니다. 노드 위치를 바꿀 때 연결선이 함께 따라오게 하기 위해서입니다.
4. 박스는 `Box`, 막대는 `Bar`, 흐름 점선은 `{...flow}`, gold 점은 `GoldDot`을 씁니다.
5. 등록하지 않은 글은 목록에서 그림 없이 제목만 보입니다.
