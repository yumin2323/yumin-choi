Owlite는 딥러닝 모델의 구조를 그래프로 탐색하고 양자화 설정을 다루는 모델 분석 도구입니다. 모델의 연산 하나하나가 노드가 되고, 텐서가 흐르는 방향이 엣지가 됩니다.

## 문제

그래프 뷰어는 엣지를 SVG로, 노드를 HTML DOM으로 그리는 구조였습니다. 작은 모델에서는 문제가 없었지만 Stable Diffusion UNet XL처럼 **노드가 4,000개를 넘는 모델**을 열면 화면이 몇 분씩 멈췄습니다. 측정해 보니 렌더링에만 172.64초가 걸렸습니다.

## 원인 찾기

느린 이유를 한 곳에서 찾기보다 그래프를 그리는 과정을 단계별로 나눠 시간을 쟀습니다.

- 노드와 엣지의 위치를 계산하는 레이아웃 단계
- 계산 결과를 화면 요소로 바꾸는 단계
- 그 사이에서 노드와 엣지를 서로 찾아 잇는 데이터 가공 단계

작은 모델에서는 드러나지 않던 비용이 노드 수에 따라 급격히 커지고 있었습니다. 특히 노드마다 전체 배열을 다시 훑는 **O(n²) 탐색**과 깊은 **재귀 처리**가 대규모 모델에서 병목이 됐습니다.

## 해결

### 그래프 규모에 따라 레이아웃 알고리즘 나누기

모든 그래프에 같은 레이아웃 알고리즘을 쓸 필요는 없었습니다. 그래프 규모를 기준으로 알고리즘을 분기해, 작은 그래프는 보기 좋은 배치를 유지하고 큰 그래프는 계산 비용이 낮은 쪽을 쓰도록 했습니다.

### 반복 탐색을 한 번의 색인으로

노드마다 배열 전체를 탐색하던 부분은 미리 한 번 색인을 만들어 두고 조회하는 방식으로 바꿨습니다. 아래는 개념을 단순화한 예시입니다.

```ts
// 전: 엣지마다 노드 배열 전체를 훑는다 (O(n²))
const source = nodes.find((node) => node.id === edge.source);

// 후: 한 번 만든 색인에서 바로 꺼낸다 (O(n))
const nodeById = new Map(nodes.map((node) => [node.id, node]));
const source = nodeById.get(edge.source);
```

재귀로 처리하던 부분도 호출 깊이가 그래프 크기에 비례해 커지지 않도록 정리했습니다.

## 결과

| 기준 모델 | 전 | 후 |
| --- | --- | --- |
| Stable Diffusion UNet XL | 172.64초 | 18.85초 |

렌더링 시간을 **89% 줄였습니다**. 몇 분씩 기다려야 했던 모델도 이제 20초 안에 열립니다.

## 돌아보며

대규모 데이터 화면이 느릴 때 원인은 대개 한 곳이 아니었습니다. 단계를 나눠 측정하고, 데이터 규모가 커질 때 비용이 어떻게 늘어나는지를 보는 것이 가장 빠른 길이었습니다.
